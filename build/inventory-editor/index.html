          What Save writes
          
        
          build/street-types/overrides.json — the durable record. The GIS pipeline merges it on every re-run and it always wins over auto-classification, so it is the permanent written record of Planning-Board and staff decisions. Every entry carries a note for that reason.
          
        
          With the checkbox ticked, the same values are also written into source/exhibits/street-types/inventory.json so Exhibit 3.1 and Exhibit 3.2 pick them up without a full pipeline re-run.
          
        
          Each write takes a timestamped backup beside the file (…json.bak-YYYYMMDD-HHMMSS); the ten most recent are kept. Nothing is written until the whole batch validates, and the write is atomic.
          

        
          Reading the table
          
        
            
          
          • Override — a human decision on the durable record. Blue rail on the left of the row.
            • 
          
          • Auto — whatever the classifier produced on the last pipeline run.
            • 
          
          • Pending — staged here, not yet written. Amber rail, and the Type cell shows old → new.
            • 
          
          • Mixed road — the road carries more than one Type. Usually worth a look.
            • 
          
          • Drift — the override and the rendered inventory disagree; an apply-to-inventory or a pipeline re-run is due.
            • 
        
          
        
          An override with a note but no value is an open item — a recorded question, not a decision. Two exist today. They are never touched unless you edit them directly.
